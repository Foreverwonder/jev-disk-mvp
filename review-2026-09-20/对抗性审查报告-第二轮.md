## 二、攻破了什么

第一轮：25 条攻击测试 → **13 红**。补了两条后又跑了 27 条 → **15 红**（最终 28 条）。

15 条红归成 **9 个真实缺口**：

| # | 缺口 | 攻击输入 | 基线（修复前）的表现 | 严重度 |
|---|---|---|---|---|
| 1 | **字符串把握度 → 整个任务作废** | `confidence: "0.9"` + 非 loss 类 | `TypeError: '>=' not supported between str and float` | **致命** |
| 2 | **inf → 界面白屏** | `confidence: Infinity` | 输出非法 JSON，浏览器 `JSON.parse` 直接抛错 | **致命** |
| 3 | **全批失败被包装成「完成」** | key 无效 / 断网 | 界面显示「完成 · 只判了 0 次」 | **高** |
| 4 | 类别闸门在把握度无效时**反而失效** | `confidence: "high"` | 结论一路走到「建议删除」 | **高** |
| 5 | bool 被当成满把握 | `confidence: true` | `float(True)==1.0` → 越判越有把握 | 中 |
| 6 | 百分制原样放行 | `confidence: 90` | 输出 90（越界），等于满把握 | 中 |
| 7 | **单边字段无效时被静默忽略** | 只缺 kind 的 confidence | `row_conf` 取另一边的 0.8，不需要人工确认 | 中 |
| 8 | 截断标志会撒谎 | 恰好 5 个文件 / 上限 5 | 报「文件太多，只统计了前 5 个」 | 中（**会显示在录屏画面上**） |
| 9 | 第三种条目凭空消失 | 非目录非文件 | 不计体积、不计跳过、不计错误 | 低 |

### 三个最该看的

**① 缺口 1 —— 上一轮的容错兜不住它**

我上一轮加的「单批失败就降级」，让异常不会冒到任务层。但这条路径的异常出在**汇总阶段**，
根本不在 `work()` 的 try 里 —— 所以照样整个任务作废。**同一个缺陷的第二个入口。**

而且它需要满足两个条件才触发：`choice` 是 program_body / app_state / user_content（不进第 3 关），
且 `kind_conf` 是字符串。**我写测试的时候差点漏掉它** —— 是在写断言时才推演出来的。

**② 缺口 2 —— inf 会让界面白屏**

Python 的 `json.dumps` 默认把 `inf` 写成裸的 `Infinity`。那不是合法 JSON，浏览器 `JSON.parse` 会抛错。
实测：

```
基线  kind_conf=inf  →  整包 JSON 出参：★非法 → 前端 JSON.parse 会抛 非法常量 Infinity
现在  kind_conf=0.0  →  整包 JSON 出参：合法
```

**③ 缺口 3 —— 降级是把双刃剑**

上一轮把「单批失败 = 任务作废」改成「单批失败 = 降级」，这是对的。
但我没考虑**每一批都失败**的情况：key 失效、断网、服务挂，三种情况长得一模一样，
用户看到的却是「完成」。

实测对比：

```
基线  state=done   phase='完成 · 20 条归并成 20 类，只判了 0 次'   error=''
现在  state=error  phase='全部失败 · 20 条没判出来'
      error='JEV 一次都没调用成功，20 条都没判出来：HTTP 401: invalid api key'
```

## 三、怎么修的

改动总量：`server.py +97 / -27`、`index.html +8 / -2`、`config.json` 零改动。

用**补丁脚本**一次做完，每个锚点必须在文件里恰好出现一次，不唯一就中止 —— **18 处锚点全部唯一命中**。

### 核心是一个口径问题

修复前，代码里只有一个 `_num()`，被同时用来处理**把握度（0~1）**和**损失分（0~3）**。
这就像拿一把尺子量身高和量体重。

所以补丁的核心是**把两套量纲分开**：

```python
_num(x, default)     # 只负责「能不能变成一个有限实数」，不管范围（0~3 的损失分也走它）
_conf01(x, default)  # 专管把握度：收敛到 [0,1]
_dict_or_none(x)     # 概率分布：不是字典就当没有
```

`_conf01` 的取舍写在注释里了：**越界的值不猜、也不截断成 1.0**。
截断成 1.0 等于「最有把握」，方向正好是危险的 —— 所以按无效处理，倒向安全侧。

### 18 处改动分布

| 位置 | 改了什么 |
|---|---|
| `_num` | 排除 bool；`isfinite` 挡住 nan/inf |
| 新增 `_conf01` / `_dict_or_none` | 两套量纲分离 |
| `score_entry` / `verdict_of` | 把握度走 `_conf01` |
| `verdict_of` 闸门 | **把握度无效 → 闸门关上**（原来是跳过） |
| 第 1 关 `on1` | `noul` 归一化 |
| 第 2/3/4 关 | `confidence` / `probabilities` / `score` 归一化 |
| 汇总 | 闸门取值归一化；`row_conf` 单边无效按零把握 |
| 输出字段 | 类型全部干净（前端不再算 NaN） |
| `stats` | 加 `degraded_why`（失败原因）+ `all_failed` |
| `run_job` / `run_judge_only` | 全挂 → 报 error，但**保留 items**（列表照常能看） |
| `expand_dir` | 多探 1 个再判截断；补 `else` 分支；返回 `other_skipped` |
| 前端 | 未计入项文案说清楚；降级提示带上原因 |

## 五、五层审查结论

> 规矩：不按"我改了哪里"审，按每一层的通用问题审；哪一层是空的要说清为什么。

### L1 事实层 —— 站得住

- 所有数字都是**本机实测**，不是引用：36 条测试、18 处锚点、+97/-27、3 次端到端、0.85/0.83/0.79。
- 交叉验证做了：diff 行数用 `difflib` 独立计算；测试数两套分开跑。
- **漏做**：24 项攻击面做了 17 项，7 项没做（见第六节）。**这是本次审查最大的诚实缺口。**

### L2 口径层 —— 有两处分歧没对齐

| 概念 | 分歧 | 我的处理 |
|---|---|---|
| 把握度 vs 损失分 | 0~1 与 0~3 混用一个函数 | **本轮已分开** ✓ |
| 「把握度无效」 | ①按零把握 ②不参与计算 ③整条丢弃 | 采用 **①**（安全工具，未知必须指向"别动"） |
| 「请求次数」 | 是"发出的请求"还是"成功的请求"？ | 实为**成功的请求**（重试用尽才算 1 次）。**未改，但界面文案「JEV N 次调用」不精确** |
| 「截断」 | `expand_dir` 已改成"确实还有更多"；`collect_files` 仍是 `>=`（恰好等于上限会误报） | **只改了一个，两处口径仍不一致** |

### L3 解读层 —— 三条结论都有反面

1. **「全批失败要报 error」** —— 反面：用户可能宁愿看到 20 条"没判出"也不要红叉。
   **应对**：报 error 的同时**保留了 items**，列表照常显示，两者兼得 ✓
2. **「无效把握度按 0 处理」** —— 反面：如果 JEV 哪天不再返回 `confidence`，所有条目会集体变成"慎重"，
   工具看起来坏了却**没有任何提示**（因为请求是成功的，不算 degraded）。
   **未解决，列为后续项。**
3. **「90 按无效处理」而不是换算成 0.9** —— 反面：若 JEV 真改用百分制，我的处理会让把握度全变 0。
   **我选保守**：换算是在替模型猜口径，猜错比保守危险。**但这是可讨论的，标注在此。**

### L4 方法层 —— 我发明的东西都标出来

- **我定的策略**（项目原本没有）：全批失败报 error；无效/越界把握度按 0；`_conf01` / `_dict_or_none` 两个新函数；
  `degraded_why` / `all_failed` 两个新字段。
- **照原口径补的**：`other_skipped`（对齐 `collect_files`）。
- **无互斥逻辑混用**：归一化是统一的，没有"一处取交集一处加权"那种事。
- **一个信息损失**：把"字段缺失"和"模型说 0 把握"揉成了同一个 0.0。
  **建议**：区分 `conf_missing: true`，别让两种完全不同的情况长得一样。

### L5 元层 —— 结论的定位

- **虚假精确**：`row_conf` 显示到小数点后两位，但实测抖动 ±0.05。
  **建议**：界面用"高/中/低"粗粒度，别给两位小数。
- **换套假设**：如果 JEV 整体改了回包字段名（而非类型），这套归一化救不了 —— 会全部走"缺失→0"→ 满屏"慎重"。
- **最有力的一击**（见第七节）。
