# JEV 硬盘体检 · MVP

一个本地小工具：选文件夹 → JEV 逐个判断 → 一屏列出哪些该删、哪些别碰，**每一行都带它的把握程度**。

**全程只读。不删除、不移动、不改名任何文件。**

> ⚠️ **改口**：之前我在多份文档里写过"界面上的删除按钮是演示态"——
> 对抗性审查发现**界面里根本没有删除按钮**，那句话一直是空头承诺。现在就按真实情况说：
> 这个工具没有任何删除入口，它只负责"看"和"判断"。要不要动手，你自己去资源管理器做。

## 跑起来（推荐：双击）

**双击 `start.bat`** —— 它会自己找 Python、自己打开浏览器。

第一次会要 API key，粘贴一次就存进 `key.txt`，以后不用再输。
（`key.txt` 已在 `.gitignore` 里，不会被提交出去。）

关掉那个黑窗口 = 服务停止。或者点界面右下角的「关闭服务」。

**没人用的时候它会自己退出**：默认 20 分钟没有任何操作就自动关闭，
免得服务一直挂着没人管。想改时长就改 `config.json` 里的 `server.idle_shutdown_minutes`，
或者启动时加参数。

### 或者手动跑

```bat
set TYPESAFE_API_KEY=apikey_xxx
python server.py
```

然后打开 <http://127.0.0.1:8849>

| 参数 | 作用 |
|---|---|
| `--port 9000` | 换端口（默认 8849） |
| `--idle-minutes 0` | 关掉自动退出 |
| `--idle-minutes 60` | 改成 60 分钟没人用才退 |
| `--no-browser` | 不要自动打开浏览器 |

依赖：**只有 Python 标准库**，不用装任何东西。（Python ≥ 3.9，实测 3.13）

## 功能

| 功能 | 说明 |
|---|---|
| **选择文件夹** | 点「选择文件夹」弹出浏览器：盘符快捷按钮 + 面包屑路径 + 子目录列表，可以直接下钻，也可以回上一级。C 盘根目录下的 `Windows` / `Program Files` / `$Recycle.Bin` 等已自动隐藏 |
| **读取各类文件名** | 一次遍历把目录树全读进内存（实测 2 万文件约 0.5 秒），统计目录体积、文件数、扩展名分布、最大的几个文件名 |
| **智能折叠** | 大文件夹折叠成一条（`node_modules` 这类"一堆小文件"不会刷屏）；大文件单独成条。规则：目录 ≥12 个文件且总量 ≥4 倍于它最大的单文件 |
| **点开看里面** | **点表格里任意一条目录**，弹出它内部的真实文件清单（按体积降序）。这就是"折叠"的可视化解释 —— 一条背后可能是 762 个文件、2.75 GB |
| **自动退出** | 没人操作 20 分钟后服务自己关闭，不留后台残骸 |
| **JEV 判断** | 每批 15 个条目、6 路并发。模型锁 `jev-1.13.0` |
| **打分** | 可删性 = 模型原始分 × 置信折扣 × 陈旧加成，再按类别和置信度封顶。全部参数在 `config.json` |
| **四个视图** | ① 处置（明细表）② 构成（按类别 + 按落点）③ 年代（按最后改动）④ 我不确定（把握 < 0.40 的） |
| **清单收窄** | 搜索框（名字 / 路径 / 类别都能搜）＋ 四个动作筛选项 ＋ 点分组条即可折叠 ＋ 「显示 N / 共 M 条」计数。几千条的清单不用再一路滚到底 |
| **筛选 / 排序** | 默认按「该做什么」分成 可以删 / 先看一眼 / 建议不清理 三组；点表头可按体积、把握、类别排序。「按动作分组」可关掉 —— 关掉就是全局排序，这时"把握最低的几条"才会真的浮上来 |
| **中止** | 扫描中可以随时中止，已判断的部分保留 |
| **用量显示** | 状态栏实时显示 JEV 调用次数、累计 input token、按 $0.042/Mtok 估算的花费 |
| **隐私提醒** | 文件名命中「私聊 / 群聊 / 密码 / 身份证 / 合同…」等词时，顶部弹红色提醒，避免截图泄露 |
| **截断提示** | 文件数超过 `max_file_scan` 上限时明确告知"结果不完整" |
| **判断口径** | 展开可看到喂给 JEV 的全部问题与选项 —— 这是工具的全部认知边界，不是黑箱 |
| **脱敏** | 三态循环：关 → 遮路径 → 遮路径＋文件名。**最大档会把路径的每一层都盖掉、只留盘符** —— 列表、展开弹窗、缓存列表统一生效。截图发公开平台用后两档 |

| 目录 | 文件数 | 条目 | 遍历 | 折叠+签名 | 全程 |
|---|---|---|---|---|---|
| `~/Downloads` | 3,033 | 48 | 65 ms | — | **1.7 s** |
| `~/Documents` | 18,224 | 3 | 0.64 s | 0.19 s | ~3 s |
| `~/.workbuddy` | 104,090 | 15 | 2.42 s | 0.96 s | **~5 s** |
| `~/AppData/Local` | 280,908 | 25 | 8.29 s | 3.55 s | **~13 s** |

| **结果缓存** | 每次扫描自动存到 `cache/`。点「载入上次结果」会**列出历次存档让你挑**（每条显示当时扫的哪个目录、什么时候、多少文件多大），回放不调用 JEV、不花额度，录屏时不用重复跑 |

### 那两个「为什么会这样」的问题

**Q：读了几万个文件，怎么只出来一百多条？**
A：大文件夹会被**折叠成一条**。规则在 `config.json` 的 `scan.collapse_min_files` / `collapse_ratio`：
一个文件夹里 **≥12 个文件**、且总量 **≥4 倍于它最大的单个文件**，就折成 1 条。
界面上每个目录行都写了「含 N 个文件」，**点它就能看到里面到底是什么**。

**Q：扫描时上面显示「读了 280,908 个文件」，但表里只有几十条？**
A：上面那个是**真实文件数**，表里的是**折叠后的条目数**。
实测：`Downloads` 3,033 个文件 → 48 条；`AppData\Local` 280,908 个文件 → 25 条。
差这么多是因为大文件夹被折成了一条 —— 点开就能看到里面。

## config.json 里能调什么

| 键 | 含义 |
|---|---|
| `scan.min_size_mb` | 多大的对象才进候选（默认 1 MB） |
| `scan.max_items` | 最多列多少条（默认 600） |
| `scan.collapse_min_files` / `collapse_ratio` | 文件夹折叠规则 |
| `weights.shrink_floor` | 置信折扣下限（默认 0.6，即最多打四折） |
| `weights.age_max` / `age_full_days` | 陈旧加成上限与满额天数 |
| `rules.kind_num_cap` | 各类别的可删性数值上限（程序本体 ≤1.0 等） |
| `rules.low_conf_threshold` | 低置信门槛（默认 0.40） |
| `rules.verdict_cap_by_kind` | 各类别能拿到的最高结论 |
| `criteria.kinds` / `criteria.deletability` | **喂给 JEV 的选项集 —— 改这里就是改这个工具的认知边界** |

## 设计要点（为什么这么做）

1. **置信度做折扣，不做加项。** 删错的代价远大于少删一点，所以不确定就往"别删"方向压。
2. **最后改动时间只加不减。** 活跃的缓存目录一直在被程序改写、mtime 很新，但它照样该删 —— 一旦允许 mtime 往下压，会大面积误伤缓存。
3. **`kind` 给 `可删性` 设上限。** 实测过模型把「程序本体」判成"可以删"，这是逻辑矛盾，必须有规则层拦。
4. **排序先分档、组内按体积。** 一个数会把"体积大"和"确实该删"混在一起，看不出排名原因。
5. **结论词用语义锚定，不用数值阈值。** 按数值切档会让「建议删除」这一档永远空掉。

## 已知边界

- 只吃文本：JEV 看不到文件内容，只能靠名称、路径、体积、时间、扩展名、文件名样本判断
- **它不知道"你还在不在用"** —— 正在使用的软件本体也会被判成"程序本体"，得靠规则和人来补
- 归档包和它解压目录之间的关系它看不出来，需要额外代码规则
- `score` 的置信度门槛（0.50）是按小样本校准的，换目录要重新看
