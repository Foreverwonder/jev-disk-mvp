## 零、一句话定位

一个**本地、只读、不删任何文件**的磁盘体检小工具：选文件夹 → 把目录/文件压成「条目」→ 用 **TypeSafe 的 JEV（判断模型）** 逐条判断「这是什么 / 删了亏多少 / 我有多确定」→ 一屏列出「可以删 / 先看一眼 / 建议不清理」，**每行都带 JEV 自报的把握度数字**。

卖点不是「AI 替你清理」，而是 **AI 会承认自己看不懂**（跟 360 那种黑箱裁判相反）。演示/录屏/发小红书用。

## 一、怎么跑起来（推荐双击）

1. 双击 `start.bat`：自己找 Python、自动开浏览器。
2. 第一次会要 API key，粘贴一次存进 `key.txt`（已在 `.gitignore`，**绝不可提交**）。
3. 关掉黑窗口 = 服务停；或界面右下角「关闭服务」。默认 20 分钟没人用自动退出。

手动：`set TYPESAFE_API_KEY=apikey_xxx && python server.py`，开 http://127.0.0.1:8849
参数：`--port 9000` / `--idle-minutes 0`（关自退）/ `--no-browser`
依赖：**只有 Python 标准库**，Python ≥ 3.9（实测 3.13）。

⚠️ **API key 安全红线**
- 真 key 在 `jev-disk-mvp/key.txt`（本机已落盘），**前端读不到、仓库不提交**。
- 代码只从环境变量 `TYPESAFE_API_KEY` 读；`start.bat` 会从 `key.txt` 注入。
- 这是体验型 key，**API 侧查不到余额**（`/v1/usage` 等全 404），余额只能登 console.typesafe.ai 看。
- **模型锁 `jev-1.13.0`**，绝不要用 `jev-latest`（会漂移）。

## 二、内部到底谁在干活（代码 vs JEV vs LLM）—— 必读

**全程没有普通 LLM 参与**（0 次生成文字）。分工如下：

| 屏幕上的东西 | 谁给的 | 说明 |
|---|---|---|
| 名称/路径/体积/文件数/改动时间 | 文件系统（扫描代码） | 纯数据 |
| **类别**（可再生缓存/安装包/程序本体…） | **JEV · 第2关 Choice** | 带 `probabilities` 分布 |
| **类别把握** kind_conf | **JEV 自带 confidence** | 0~1 |
| **删除损失分** | **JEV · 第3关 Score** | 只对可能是垃圾的问 |
| **损失四档分布** | **JEV probabilities** | 第3关返回 |
| **摇摆标记** | JEV 分布 → 我的阈值 | `swing_gap` 是代码定的 |
| 第1关过没过（认名字） | **JEV · 第1关 Noul** | 认不出直接「看不懂」 |
| 可删性 `d_final` | **代码公式**（JEV分 × 置信折扣 × 陈旧加成） | 公式是人写的 |
| 结论档位（别碰/慎重/可以考虑） | **代码规则**（类别封顶 + 置信闸门） | 规则压倒模型的地方 |
| 可以删/先看一眼/建议不清理 三组 | **纯界面规则** | ≥5GB 或 把握<0.6 就挪走 |
| 「依据(规则)」那行小字 | 本地正则 | 跟 JEV 无关 |

**一句话**：文件系统给事实，JEV 给语义（是什么/亏多少/多确定），**我的规则给框架（定档、封顶、分组闸门）防止 JEV 判错时出事**。地基是 JEV 打的，兜底是我的规则。证据原文见 `docs/JEV-功劳核查.md`。

### 四关编排（学 jev-review 的阶段性门控）
1. **Noul 认名字**：把握 < `recognize_floor`(0.5) → 判「看不懂」，后面不再问（省钱+杜绝瞎猜）。
2. **Choice 类别**：程序本体/应用状态/用户产出 → **第2关直接定档「别碰」，不问损失**；只有缓存/构建产物/安装包进第3关。
3. **Score 删除损失**：只对第2关筛出的「可能是垃圾」问。
4. **Choice 同签名一组是否一致**：特征相同的归一类，代表（组内最大）判一次，答案映射回全员（学 pg_typesafe 去重，省 token）。

### 特征去重 / 折叠（扫描侧，代码活）
- `sig_key = (is_dir, 体积量级, 文件数量级, 扩展名+数量分桶)`，同类只判一次（Downloads 实测省 ~58% 调用）。
- 大文件夹折叠成一条（`collapse_min_files`≥12 且总量≥4×最大单文件）；`collapse_max_gb`(4) 以上的「又大又碎」目录不整块折、往下拆一层（否则 58GB 一行看不出内容）。

## 三、关键设计决策（第一性原理，别乱改）

1. **删错代价 >> 少删代价** → 不确定一律往「别删」压（置信度做折扣不做加项）。
2. **mtime 只能往上加不能往下压** —— 活跃缓存一直被程序改写、mtime 很新但照样该删；允许 mtime 往下压会大面积误伤缓存。
3. **`kind` 给可删性设上限** —— 模型曾把「程序本体」判成"可以删"，逻辑矛盾，必须有规则层拦（`verdict_cap_by_kind`）。
4. **排序先分档（可以删→先看一眼→建议不清理）组内按体积**，不把"体积大"和"真该删"乘成一个数混掉。
5. **结论词用语义锚定+规则降级，不按数值阈值切档**（按数值切会让「建议删除」永远空档）。
6. **≥5GB 安全闸**（`ui.warn_size_gb`）：超大件误删代价不对称，强制进「先看一眼」。这是 2026-09-20 从 `whisper_models` 危险回归里长出来的保命闸。
7. **全程只读**：没有任何删除入口（界面没有删除按钮，别再写"删除按钮是演示态"那种假话）。

## 八、本机环境坑（若新 AI 在这台机器上跑/调试）

- **shell `ls`/`curl` 是坏的**，发 HTTP 用 PowerShell `Invoke-WebRequest` 或 Python。
- **托管 node(22.22.2) 的 npm/npx 是坏的**，要用系统 `C:\nvm4w\nodejs\npx.cmd`。
- PowerShell stdout 可能被环境吞 → 结果 `Out-File` 到文件再读。
- 含中文的输出让 Python 直接写文件，别过 PowerShell 管道（会二次编码）。
- 前端逻辑验证：把 `index.html` 里目标函数区间**原样抽出来**，Node 里拼 preamble + 真实缓存数据跑断言（别装浏览器）。
- 黑窗口开着才服务在；`?v=N` 绕预览缓存。
- ★ **`os.symlink` 在这台机器上会静默失败**：返回成功、不抛任何异常，但链接**根本没建出来**
  （`os.listdir` 里查不到，`os.path.lexists` 为 False）。2026-09-20 实测坐实。
  ⇒ 任何依赖符号链接的测试都要用 `os.path.lexists()` 复核结果，别信返回值；
  造不出样本时改用 mock 直接测分支逻辑（见 `test_adversarial.py` 里
  `test_non_file_non_dir_entries_are_accounted`）。
- ★ **跑本机 Python 测试时，别让输出过 PowerShell 管道**（中文会被二次编码成乱码）。
  可靠做法：写个小 runner，在 Python 内部 `sys.stdout = io.StringIO()` → 跑完
  `open(path, "w", encoding="utf-8")` 一口气写文件 → 再读那个文件。
  **两个必备细节**：① `unittest.main()` 会把 `sys.argv` 当测试选择器，
  runner 里必须先 `sys.argv = [target]`，否则报 `module '__main__' has no attribute '<路径>'`；
  ② `unittest discover -s tests` 在 `tests/` 没有 `__init__.py` 时会报
  `Start directory is not importable` → 改成按文件 `importlib.util.spec_from_file_location` 加载。
- `tests/js-syntax-check.cjs` **必须带文件参数**（`node js-syntax-check.cjs index.html`），
  不传会 `readFileSync(undefined)` 崩；它自己会把结果写到 `%TEMP%\uf_js_syntax.txt`，读那个比看控制台可靠。
