## L2 口径层

- **「别碰」一词的含义在重构后变宽了**：既包括"模型判删除损失大"，也包括"第 2 关定了类别、损失分根本没问"。同一档位、两种证据。UI 用「未问损失分」区分了这两种情况，自洽。
- **「省 28 次判断」≠「省 58% 的钱」**：去重省的是"问题次数"，但每关都要重发一遍条目描述（state 文本才是 token 大头）。已用「每关只送它需要的信息」（第 1/4 关送短描述）把 token 从 23,802 压到 **19,457（-18%）**。界面文案说的是"判断次数"，没吹省钱 —— 口径自洽。
- **「摇摆」是双条件**：top1 领先 < 0.2 **且** top2 ≥ 0.25。只写一个会把"全体都摇摆"或"永远不摇摆"的极端情况放进来。已写进 config 注释。

## L5 元层

- **虚假精确**：`d_final` 显示两位小数，但模型同输入抖动 ±0.1。主表以**结论档位（4 档）**为主、小数为辅；diff 卡已明确提醒。
- **敏感性测试**：把认出门槛 0.5→0.3 重判 —— **0 条档位变化**。说明这个门槛在这批数据上不敏感（没乱拦人），也说明 diff 的档位层是稳的。
- **最有力的推翻角度（自己写出来）**："Downloads 上第 1 关拦下 0 条、第 3 关只问 2 类 —— 四关编排在这批数据上几乎没体现结构价值。"
  **承认**：Downloads 本来就干净；编排在这批数据上省的是钱（去重 58%、token -18%），它的结构价值要在 AppData 级别的脏目录才显形。**这次演示数据的干净是边界**。
- **结论定位**：这是"演示四关编排 + 去重 + 分布 + 可改口径"的 MVP，**不是清理建议的权威**。
