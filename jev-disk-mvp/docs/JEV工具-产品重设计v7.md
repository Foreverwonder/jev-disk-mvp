# 从产品经理的角度，重看这个工具

> 日期：2026-09-20
> 起因：用户反馈「这个排序还是有点怪怪的」「现在这一套更像是你自己发明的，不符合人用的」

---

## 一、市面上的磁盘工具，逻辑其实分成两家

不是"清理工具"一个品类，是**两个互不覆盖的品类**：

| | **分析类** | **清理类** |
|---|---|---|
| 代表 | WizTree · SpaceSniffer · TreeSize · DaisyDisk · WinDirStat | CCleaner · Dism++ · BleachBit · 360 · Windows 存储感知 |
| **靠什么找到目标** | 扫盘，按体积找"胖子" | **它不扫盘** —— 查一份内置的「已知垃圾路径」清单（CCleaner 的 winapp2.ini），逐个路径去看有没有东西 |
| 组织方式 | 树图 / 按体积的文件夹列表 | **按类别分组**（Windows 临时文件 / 浏览器缓存 / 各 App 缓存…） |
| 排序 | **体积**，永远是体积 | 类别内按体积 |
| 给不给「该不该删」 | **不给。** 只告诉你哪里大 | 给 —— 它列出来的**定义上就是可删的** |
| 删除时机 | 它不删，你自己去删 | **两阶段：Analyze（预览）→ Run Cleaner（执行）** |
| 默认勾选 | 无 | **高确定性、低风险的默认勾上** |
| 兜底 | — | 跳过系统路径、跳过正在使用的文件、个人文件永不进列表 |

**七个共同点，全部一致：**

1. **两阶段**：先给你看要删什么、能腾多少，你点了才动。删除不可逆，这是唯一正确的做法。
2. **按「类别」组织，不按单个对象。** 类别是稳定、可解释、能复用的单位。你不会看到"2024-03-11 的某个 .tmp 文件"，你看到的是"系统临时文件 1.2 GB"。
3. **体积是唯一的主排序维度。** 因为这类工具的目标函数只有一个：腾出空间。
4. **不给「分数」。** 给的是勾选框 + 体积 + 一句人话说明。没人给文件打 2.42 分。
5. **默认值就是安全声明。** CCleaner 连私人文件都不放进列表；360 那种全默认勾选是它被骂的原因。
6. **分析和清理分工，不混淆。** SpaceSniffer 明确写"我只负责分析，不负责删除，绝对安全"——它把这个当成卖点。
7. **深度工具被骂的点，恰好是我们的同款毛病。** Dism++ 的差评集中在「清理项后面没有通俗解释、没有风险等级，只有一个专业名词，不敢勾」。

## 二、我们现在站在哪 —— 三个症状

我们这工具同时想做分析（给分数排序）和清理（给删除建议）。**结果两头都不讨好。**

### 症状 1：我们用一个"分类器"去干"分析器"的活

WizTree 排序排的是"谁大"——**客观、可验证、看完就知道下一步干什么**。
我们排序排的是"谁该删"——**主观、会变、而且用户没有能力验证它对不对**。

结果就是你截图里那个感觉：「排是排了，但我不知道该信哪一行。」

### 症状 2：「分档 → 组内按体积」这个排法，第一眼看不懂

```
1  whisper_models        37.1 GB   可以考虑
2  APK Easy Tool.zip     49.6 MB   可以考虑
3  input.mp4              2.7 MB   可以考虑
4  磁盘空间分析器.exe      2.2 MB   可以考虑
5  whisper_output         4.78 GB  慎重      ← 咦？怎么又大了？
```

第 1 行 37 GB，第 2 行掉到 49 MB，第 5 行又跳回 4.78 GB —— **读的人会以为排序坏了。**
第一性原理没错（建议删的排前面），错在**中间那条规定没有画出来**。

✅ **已修**：分档从"排序规则"变成**可见的分组标题**，中间有一条带档名和合计体积的横杠。

### 症状 3：48 行榜单里，真正重要的只有 3–4 行

实测 E 盘：48 条候选，**一条 `whisper_models` 就占了 73% 的空间**。

```
48 条  =  50.59 GB
 1 条  =  37.05 GB   ← 一条占了 73%
47 条  =  13.54 GB
```

**榜单很长，信息很少。** 这是"排行榜"这个形态的固有缺陷：它逼你把注意力平均分配给 48 行，而实际上那 47 行加起来还不如第 1 行重要。

## 三、重设计：7 条产品原则

### ① 结论先行
打开先看到**一句话**，不是一张表。

```
❌ 现在：已分析 48 项 · 候选可清理 50.6 GB · 其中建议删除 0 项 · 平均把握 0.55
✅ 应该：E 盘最大的 4 样东西占了 92% 的空间。
        其中 1 样是同一份 Whisper 模型被存了 4 遍（34 GB），
        3 个格式是多余的，你正在用的那个只占 2.9 GB。
```

### ② 按类别分组，不按对象排名
类别是人能记住、能批量决策的单位。`40 个零散 .log 文件` 是一条信息；`40 个文件按可删性排了一遍` 是四十条噪音。

### ③ 一个类别一个动作，不是一个对象一个动作
市面工具全是这么干的。用户的心智模型是"浏览器缓存这一类我不要了"，不是"我要逐条审阅 47 个文件"。

### ④ 默认安全：任何「删了要重下/重建」的都不默认勾
这条市面工具做得很硬，我们太软 —— 我们甚至给了「可以考虑」这么大的一个筐，把 37 GB 的模型和 2 MB 的安装包放在同一档里。

### ⑤ 用时间说代价，不用 GB 说
```
❌ 23.0 GB
✅ 删了以后想再转一次模型，要重下约 40 分钟
```
「GB」是抽象数字，「40 分钟」是你能感知的代价。这一条对"值不值得"的判断力差一百倍。

### ⑥ 「我不确定」必须融进正文，不能藏成第 4 个 Tab
现在「我不确定」在四个视图的第 4 个 —— 它是这工具**最独特、最值钱的一屏**，却被放在最角落。
正确做法：**在每一行/每一张卡上就地标注**"这个我看不准，你自己看看"，而不是让用户主动去翻一个 tab。

### ⑦ 没得清，就说没得清
360 会给你硬凑 5 GB。诚实的工具应该说：

> 「你这盘很干净。50.6 GB 的"大件"里，真正可以安全释放的只有 8.3 GB，
>  而且全是别人留下的残骸 —— 没有一样是你在用的东西。」

**E 盘现在就是这个情况**（「可以考虑」档缩水到 50 MB）。这不是工具的失败，是它诚实。

## 五、这一轮已经改掉的

| 改动 | 说明 |
|---|---|
| **表头可点击排序** | 「体积 / 可删性 / 把握 / JEV判定」四列，点一次排、再点一次反向，带 ▼▲ 箭头。和 WizTree、TreeSize 的操作方式一致 |
| **分档从"排序"改成"分组显示"** | 表格里出现 4 条组标题（档名 + 项数 + 该档合计体积），中间有了可见的边界 |
| **顶部那排按钮瘦身** | 原来 3 个排序按钮 + 4 个筛选按钮，现在「分档显示」一个开关 + 表头排序 |
| 默认排序 | 分档显示 + 组内按体积▼ |

### 验证结果（把真实代码抽出来喂真实数据跑的）

```
A 分档模式下档位单调 = true
B 组内体积递减       = true
C 不分档时整表体积递减 = true
D 方向翻转后能翻回来   = true
E 各组项数合计 48 = 总条目 48 → true
```

## 六、下一步的取舍（要你定）

1. **要不要做第 0 屏的「一句话结论」？** —— 它是最大的一处改动，也最能让这东西"不像 360"。
2. **分类卡片要不要自动聚合？** —— 现在后端是按目录折叠的，要再聚一层成"类别卡"。工作量中等。
3. **「我不确定」怎么就地标注？** —— 建议在每个低置信行加一条黄边，而不是单独一屏。
4. **默认把「慎重」档折叠起来吗？** —— 市面工具都这么干（只显示建议项）。但你上次说想看到"一大堆文件"，所以这条我留给你定。
