## 一、先回答：那个「热力网格」是什么，为什么撤

它原本是这么个东西：把 600 个文件变成 600 个 9px 的小方块，铺成一片，方块颜色深浅代表分数。

**好处**：一眼看出整体分布，截图时很"满"。
**坏处（致命）**：**你读不出哪个方块是哪个文件。**

```
████████████▌█████████████████████▌
█████▌████████████▌████████████████
█████████████████▌█████████████████   ← 这片东西，你说得出第 3 行第 17 个是什么吗？
```

**它只能当氛围图，当不了主视图。你说它不明确，是对的。撤掉。**

---

## 二、新主视图：一屏密集清单

就是 v2 里那个「建议清理」小框，**放大成整个页面的主体**。

### 列设计

| 列 | 宽度 | 内容 | 来源 |
|---|---|---|---|
| # | 26px | 排名 | — |
| **对象** | 自适应 | 路径（超长省略号）+ 第二行灰色小字「依据（本地规则）」 | 名称=扫描，依据=**规则** |
| **体积** | 60px | 右对齐 | 扫描 |
| **删了后悔** | 74px | 数字 + 横向色条 | **JEV** |
| **把握** | 52px | 色块 chip（绿/黄/红） | **JEV** |
| **它认为它是** | 104px | 主类别 + 百分比 + 3 段微缩概率条 | **JEV** |

### 一屏能看多少行（实算）

```
表格视口高度 560px ÷ 行高 26px = 一屏 21 行可见
```

截图截这一屏就是 **21 行**，已经足够"一大堆"。
实际共 600 行 → 总长 15,600px，但因为**视口固定 + 自滚动，页面本身永远不变长**。

> 这解决了你之前"不要长图"的要求：**内容很多，但版面恒高。**
> 想更密的话还有一招：**改双栏**，一屏能到 40+ 行。要不要上，你定。

### 分层标注（做在行内，不藏页脚）

每行第二行灰字直接写：`依据（本地规则）：路径含 cache/log`
旁边 JEV 的三列不标来源 —— **因为规则和模型就摆在同一行里，一眼分得清。**

## 三、动效改法：从"格子闪烁"改成"逐行流入"

| 版本 | 动效 | 观感 |
|---|---|---|
| v2 网格 | 600 个方块淡入 + 变色 | 好看但**读不出内容**，只是背景在动 |
| **v3 清单** | **一行一行从顶部插进来，新行闪一下绿，旧行往下推** | **真的能看到"东西在往外冒"** |

新的时间轴（全部在 2 秒内）：

| 时间 | 发生什么 |
|---|---|
| 0.0s | 点「开始扫描」 |
| 0.1s | 第一批 15 行**同时插入**（不是逐条，逐条太慢），新行底色淡绿→透明（0.5s 褪去） |
| 每 115ms | 再插 15 行 → 600 行约需 **4.6 秒** |
| 持续 | 顶部四个数字跟着往上涨 |
| 完成 | 最后一批落定，按钮变「重新扫描」 |

**"哗哗哗"的感觉来自这里**：每 115ms 推进 15 行，肉眼看到的是**一串串往下掉**，比格子那种均匀闪烁更"有料"。

**提速**：按体积降序分批 → 最上面几行 0.2 秒内就有 JEV 结论。

## 四、交互（比 v2 多了三个，都很实用）

1. **筛选 chip**：`全部 / 可以信 / 复核 / 必须人看`
   点一下只显示那一档 —— 这一下最适合截图"看看它自己承认多少次不确定"
2. **排序切换**：`建议力度`（体积 × 可删性）↔ `体积`
   摆两个排序本身就是内容："按体积排是这些，按该不该删排就变了"
3. **整表滚动**：滚轮浏览全部 600 行
