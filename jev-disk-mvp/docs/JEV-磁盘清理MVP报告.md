## 四、它翻车的地方（5 处，其中 2 处危险）

**🔴 最危险：6 个 `.git` 对象文件，被判成 5 种不同的东西**

```
.git/objects/28/5d8481… → build_output      删 1.87  置信 0.00
.git/objects/cd/526ca0… → user_output       删 1.77  置信 0.02
.git/objects/94/408bfc… → build_output      删 1.70  置信 0.04
.git/objects/1f/d60ba8… → build_output      删 1.59  置信 0.17
.git/objects/73/035f64… → regenerable_cache 删 1.42  置信 0.16
.git/objects/6e/70281a… → build_output      删 1.33  置信 0.13
```

这 6 个是**同一种东西**（Git 的对象库），它却分了 3 个类、删分从 1.33 到 1.87 铺开。
而且 `build_output` 这个标签**最要命** —— 它会让人以为"有源代码就能重新生成"。**实际上删了直接毁掉仓库。**

这正是我上一轮说的：**它读不懂就猜**。文件名是一串哈希，里面没有语义可抓。

**🟡 第二危险：正在用的软件本体，删分给高了**

`v2rayN.exe`(1.98)、`mihomo.exe`(1.97)、`xray.exe`(1.96)、`sing-box.exe`(1.94) ——
这四个是**桌面上的代理客户端本体和它的内核**。你本机明显在用（代理端口 10808），删了代理直接废。
它类别判对了（`install_artifact`），但**"删了不后悔"的分给到了 1.94~1.98**。

**🟡 第三：和你的磁盘清理 skill 记的规矩打架**

`marktext-setup.exe`(149MB) 它判删分 2.00。但你那份 skill 里明确记着
**"未安装软件的安装包不能删，用户可能还要用"** —— MarkText 就是当时点名的那个。
⇒ 这类**规则赢，模型输**。

**🟡 第四：QQ 表情资源包被当成纯缓存**

`sysface_res.zip` 判 `app_data_state` 删 2.22、两个 `sysface`/`PullNormalEmoji` 判 2.82~2.90。
这些是 QQ 的表情资源包，删了可能**表情显示异常**，不是无感。

**🟡 第五：归档包和它的解压目录，它没看出关系**

`project_20260514_175130.tar.gz`(161MB) 判 `user_output` 删 1.27 —— 这个分数偏保守，没问题。
但它**没意识到**同目录下还有一个 `project_20260514_175130\` 解压目录。
你那份 skill 的坑 9 专门写过：**归档条目数和解压后文件数对不上时，不能假定互为副本**。
这正是它最弱的能力——**跨对象的关系推理**（上一轮实测过：跨字段多跳它只有 0.36）。

## 五、最有价值的发现：confidence 真的在干活

把 30 个候选按 **JEV 自己报的置信度**切两半，规律非常干净：

| 置信度 | 数量 | 表现 |
|---|---|---|
| **≥ 0.60**（它说"我确定"） | 5 个 | 安装包类，**判得都对** |
| 0.40 ~ 0.59 | 13 个 | 缓存类、下载视频，方向大体对 |
| **≤ 0.28**（它说"我在猜"） | 12 个 | **6 个 git 对象全部落在这里**，加上下载视频、tar.gz |

**6 个错判，全部落在"置信 ≤ 0.28"那一堆里。**
第 15~25 行那些 0.00 / 0.02 / 0.04 / 0.13 / 0.16 / 0.17 —— 它在**诚实地说"我不知道"**。

⇒ 这就把 30 个候选干净地切成了**"可以信的一堆"** 和 **"必须人看的一堆"**。
这个机制在这批数据上是真的能用的。

## 六、结论：你这个点子怎么修

**你的点子成立，但它只能当侦察兵，不能当法官。**

**它能干的（而且干得不错）：**
- 从一堆"名字看不出是什么"的东西里，粗分出三六九等
- 对"缓存 / 安装包 / 着色器缓存"这类有明确语义特征的对象，判得又快又准
- **用 confidence 诚实地标出"我没把握"** —— 这一条最有价值

**它干不了的（不是它笨，是它拿不到信息）：**
- **它不知道你在不在用。** 代理内核和 v2rayN 就是活例子：类别对，但它不知道你天天在用
- 哈希名、纯数字名这类无语义对象 —— 它只能猜（好在它自己知道）
- 对象之间的**关系**（归档 vs 解压目录、同一个软件的多个副本）

**所以正确的分工是：**

```
第 1 道：规则（确定性）—— 临时目录 / 缓存路径 / 超期大文件  → 直接可删
第 2 道：JEV（语义）—— 名字看不出是什么的 → 给类别 + 删分 + 置信度
第 3 道：人 —— JEV 置信 < 0.5 的、涉软件本体/个人内容的  → 必须你点头
```

**判据排序也建议改一下**：不要用 JEV 的"使用价值分"当主排序（它没法知道），
改成 **体积 × 可再生成程度**，JEV 只负责提供"可再生成程度"和"置信度"这两列。
