# 磁盘工具的 JEV 化重构方案（v8）

> 日期：2026-09-20
> 前提：**不换方向、不做别的工具。** 就是把这个磁盘清理/分析工具做对。
> 方法：把 GitHub 上验证过的 JEV 项目模式，逐个搬到这个工具里。

---

## 〇、先纠正我上一轮的两个错

1. **我跑题了。** 用户要的是"参考 GitHub 的 JEV 项目优化磁盘工具"，我答成了"换个东西展示 JEV"。
2. **"载具选错"说重了。** 准确的说法是：**方向对，但现在这层实现把 JEV 用成了配角。**
   现状：每条对象只问 2 个问题（是什么 + 删了多亏），然后大部分结论被我的规则覆盖
   （类别封顶、置信度闸门、体积折扣）。JEV 在这套流水线里只贡献了一个弱信号，
   所以它最有意思的东西——分布、速度、编排、校准——全都看不见。

**修正后的判断：磁盘清理场景完全装得下 JEV，而且比大多数场景更合适**——
因为它天然是"海量对象 × 同一组判断"，这正是 JEV 的主场（批量、便宜、快）。
问题只在用法。

## 一、从 GitHub 项目里搬什么：四个模式 → 四个改动

### 改动 1：把"一次问两个"改成"分阶段过关" —— 学 jev-review（358★）

jev-review 的核心不是"问了很多问题"，是**编排**：Noul 风险矩阵 → Choice 文件画像
→ Choice 证据选择 → Choice 机制分类 → Score 严重度 → 条件路由。
**上一问的答案决定下一问问什么，低置信的半路就被拦下。**

现在：每条 2 问，一次性问完，不管三七二十一。
改成四关：

```
第 1 关  Noul   「光看这个名字和路径，你能认出它是什么吗？」
            ├─ 把握 < 0.5 → 直接进「看不懂」，后面不问了  ← 省钱，且不再瞎猜
            └─ 过
第 2 关  Choice 「它属于哪一类？」
            ├─ 程序本体 / 应用状态 → 到此为止（结论已定：别碰）
            └─ 缓存 / 构建产物 / 安装包 → 过
第 3 关  Score  「重新拿回来的代价多大？」   ← 只对"可能是垃圾"的问
            └─ 过
第 4 关  Choice 「这批同签名的要不要一起处理？」（批量级，不是单条级）
```

**为什么这值得做：**
- 省钱：认不出的不再浪费两问；程序本体的不再问重建成本。估算 token 降 35~50%。
- **编排本身变成可看的**：界面上能看到"这一条走到第几关被拦下"——这是 jev-review
  最值得抄的地方，也是现在完全没有的。
- 它天然修掉 whisper_models 那种翻车：认不准的，第一步就进"看不懂"，
  不可能再给"可以考虑删"。

### 改动 2：按特征去重，判一次管一批 —— 学 pg_typesafe（78★）

pg_typesafe 的招牌数字：1000 条 NYC 投诉去重成 38 种，**1 次请求 0.86 秒**（逐条 23 秒）。

现在：48 条对象就发 48 组问题（4 批）。
但这里面大量对象**特征雷同**——E 盘上 5 个 shader cache 目录长一个样、
十几个 `程序本体` 的签名几乎一致。

改成：按签名（体积段 + 扩展名分布 + 路径模式）聚成"等价类"，**每个等价类判一次**，
答案映射回全部成员；成员里置信度最低的那个单独复问一次兜底。

**为什么这值得做：**
- token 再省一截，600 个对象可能只需要判 200~300 个特征。
- **"600 个对象 · 2.1 秒 · $0.004"变成界面上的标题数字** —— pg_typesafe 证明这是
  最能打动开发者的展示方式。
- 顺手把"去重比"显示出来，观众一眼看懂它为什么这么快。

### 改动 3：把"分布"提到台前，不再只给一个数 —— 学 neo4jev（36★）

neo4jev 不取 JEV 的结论，**取整条概率分布当搜索信号**。

现在：可删性显示成一个数（2.42/3）+ 一根小条；类别显示 top-1 + 一条小概率条。
改成：
- **可删性那列直接画 4 格分布**：`绝对不能删 / 最好留着 / 可以删 / 放心删` 各占多少。
  一个数会骗人（1.91 可能是 0.82 的"可以删"+0.09 的"放心删"堆出来的），
  分布不会。
- **类别摇摆直接标出来**：当 top1 和 top2 接近（比如缓存 0.53 vs 程序本体 0.39），
  这行打上「它在这两类之间摇摆」——**这正是该你自己看一眼的信号**，
  也是 360 / CCleaner / WizTree 任何一个工具都给不出的东西。
- whisper_models 那种 case 会自己显形：它的分布就是 0.53 vs 0.39，摇摆明明白白。

### 改动 4：标准可改 + 一键全盘重判 —— 学 playground 的 A/B 和 CV screener 的"policy changed → re-score free"

这是四个里**最值钱的一个**。

现在：「判断口径」面板是只读展示，改标准要改 config.json 重启。
改成：口径面板变成**可编辑**——选项描述、档位说明、阈值都能在界面上改，
点「按新标准重判」，几秒后整张表按新口径刷新，还能和旧口径**并排 diff**
（哪些条的结论变了、变了多少）。

**为什么这值得做：**
- 这是对 360 / CCleaner 的**本质区别**：它们的规则是写死在代码里的，
  你永远改不了"它认为什么算垃圾"；这里你的标准是活的，改完几秒钟全盘重判，
  成本几分钱。
- 这也正是 JEV 官方生态认可的用法（CV screener 的卖点就是"政策改了，重算免费"）。
- **演示价值最高**：录屏里改一句"安装包也留着"，点一下，
  600 行数据的结论哗哗地重排——这是任何传统清理工具做不到的画面。

## 二、改完之后这个工具会变成什么样

| | 现在 | 改完 |
|---|---|---|
| 判断方式 | 一次 2 问，一条一判 | **四关编排**，上一问决定下一问 |
| 速度 | 48 条 1.7 秒（没当卖点） | **600 条 ≈ 2 秒，去重比 + 毫秒数 + 花费挂在标题上** |
| 结论呈现 | 一个数 2.42/3 | **4 格分布** + 摇摆标记 |
| 口径 | 写在 config.json 里，改了要重启 | **界面上改，一键全盘重判，新旧并排 diff** |
| 低置信 | 藏在第 4 个 tab | **就地显示**：摇摆标记 + 走到第几关被拦 |

一句话定位也跟着变了：

> 360 回答"这是什么垃圾"（写死的规则）。
> 这个工具回答"**我觉得这可能是什么，我有多大把握，你可以自己改标准**"。

已有的好东西保留：表头点击排序、分档组标题、展开看目录内部、隐私打码、空闲自退。

## 三、顺序和工作量

| 步 | 内容 | 工作量 |
|---|---|---|
| 1 | 改动 3（分布上台前 + 摇摆标记） | 半天，**纯前端，不重跑判断** |
| 2 | 改动 2（特征去重） | 半天，省 token 且提速 |
| 3 | 改动 1（四关编排） | 一天，要改 server 的判断流程 |
| 4 | 改动 4（口径可编辑 + 重判 diff） | 一天 |

建议 1 → 2 → 3 → 4。第 1 步不花 API 钱、见效最快；第 4 步是最大卖点，放最后做扎实。
