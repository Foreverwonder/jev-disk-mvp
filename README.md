# JEV 硬盘体检

给「这个文件夹到底能不能删」这个问题，请一个**会说自己没把握**的 AI 来判。

选一个文件夹 → 逐个判断 → 一屏列出哪些能删、哪些别碰，**每一行都带着它的把握程度**。
全程只读：不删、不移、不改名，界面里根本没有删除按钮。

---

## 仓库里有什么

| 路径 | 是什么 |
|---|---|
| `jev-disk-mvp/` | **工具本体**。一个 Python 服务 + 一个 HTML 界面，零第三方依赖 |
| `jev.py` | JEV 的最小客户端（命令行直接问几个问题），工具之外顺手的调试入口 |
| `review-2026-09-20/` | 一次完整的对抗性评审：怎么被挑刺、怎么按 TDD 修、改前改后的 diff 与截图 |

想直接用，看 [`jev-disk-mvp/README.md`](jev-disk-mvp/README.md)。

```bash
cd jev-disk-mvp
start.bat          # 双击也行：自己找 Python、自己开浏览器
```

只要 Python ≥ 3.9（实测 3.13），**不用装任何东西**。

## 它跟别的「磁盘清理」不一样在哪

**1. 它会承认自己看不懂。**
把握度低于 0.40 的条目单独占一个页签，配一句人话解释为什么不敢下结论。
它们既不会被塞进「可以删」，也不会被丢进「建议不清理」——就是明明白白告诉你「这个我看不准」。

**2. 它不给「垃圾 12.3 GB」这种结论。**
每条都摊开依据：类别、体积、最后改动时间、含多少个文件。
连喂给模型的**全部问题与选项**都能展开看——这是它的认知边界，不是黑箱。

**3. 它不替你动手。**
工具只负责「看」和「判断」。要不要删，你自己去资源管理器。

**4. 它的判断是可以被推翻的。**
所有阈值、权重、判据、选项集都在 `config.json` 里，代码里不写死任何一条。
觉得哪条判得不对，改配置重跑，不用读代码。

## 背后的东西

判断能力来自 TypeSafe JEV（System One 模型），版本锁 `jev-1.13.0`。
锁版本是因为 `jev-latest` 这类别名会漂移，阈值会莫名其妙失效。

用之前需要自己的 API key（`key.txt` 已被 `.gitignore` 排除，不会进仓库）：

```bash
set TYPESAFE_API_KEY=apikey_xxx
python server.py
```

## 一些实测数字

| 场景 | 规模 | 结果 |
|---|---|---|
| 遍历 D 盘整盘 | 118 万文件 | 12.9 s（另加归纳 8.6 s） |
| 一次完整判断（`D:\AI_Projects`） | 48 万文件 | 12 次调用 / 64,087 token / **$0.0027** |

便宜的原因是它不把每个文件都丢给模型：先把目录折叠成条目，再把同类条目归并成一批问一次。
归并这一步在一次实测里省掉了 113 次调用 —— 这是这个工具省钱的全部秘密。

## 已知边界

- 只吃文本：模型看不到文件内容，只能靠名称、路径、体积、时间、扩展名、文件名样本判断
- **它不知道「你还在不在用」**——正在使用的软件本体也会被判成「程序本体」，得靠规则和人来补
- 归档包和它解压出来的目录之间的关系，它看不出来
- 只在 Windows 上实测过（`os.scandir` + NTFS 重解析位那套是 Win 特有的）
